# 情緒天氣 設計手冊

把「用天氣記錄心情、累積成一張會變化的個人氣候圖」這個方向整理成一份設計文件：概念、核心機制、差異化賣點、避坑教訓、商業模式、技術平台、畫面框架、資料模型、待決事項。之後每次討論有新決定，這份文件會再更新。

> 這份手冊沿用「許願池」專案同一套成功邏輯：**使用者的行為直接長出畫面上的東西，而不是做完事另外給一個無關的小遊戲。** 只給正回饋、不給罪惡感、一句話能講完。

---

## 01 概念

- **核心體驗：** 每天用「今天心情是什麼天氣」記錄情緒（晴、多雲、陰、雷雨、霧、雪…），一次一個動作就完成。長期累積成一張**會變化的個人情緒氣候圖**，或一個隨心情變化的小世界。
- **一句話定位：** **「一本美到每天想打開看的心情天氣紀錄。」**
- **明確不做什麼：** 不宣稱有心理治療或診斷效果、不做情緒量表評分（那會有壓力、也踩醫療器材的線）。定位是情緒陪伴與自我覺察的娛樂體驗。
- **差異化的核心：** 市面情緒 App 兩種極端——太醫療化（像做心理測驗，有壓力）或太陽春（打個表情符號就沒了）。這個方向切中間的空缺：**美到想每天回訪、有情感回報、但零壓力。**

---

## 02 核心機制

**1. 一天一次的「天氣打卡」**
- 主動作極簡：打開就選一個天氣代表今天心情，可選填一句話或幾個標籤（工作／關係／身體…）。
- 這個「選天氣」的動作本身要有儀式感（動畫＋音效），像許願池投香油錢那樣的收心小動作。

**2. 情緒氣候圖（累積視覺化，最有黏性的部分）**
- 把每天的天氣累積成一張可回看的「氣候圖」：月曆式的天氣格、或一整年的氣候色帶。
- 使用者看得到「這個月我大多是晴天」「上週連續陰雨」——**看見情緒的模式本身就是價值**，這是別的 App 沒做好的。

**3. 會回應心情的小世界（可選的進階呈現）**
- 除了圖表，可做一個隨近期心情變化的小世界／小場景（晴天多就繁榮明亮，陰雨多就轉為靜謐的雨景）。
- 關鍵原則：**世界的變化是心情紀錄的直接結果**，不是額外獎勵，也不對「壞心情」做懲罰——陰雨天景也要是美的、被接納的，不是「你不好所以世界變醜」。

**4. 溫柔的回顧與覺察**
- 「一年前的今天你是什麼天氣」「你已經連續記錄 30 天」這類回顧，做為回訪與情感黏性來源。
- 可加輕量的自我覺察提示（例如「這週雷雨比較多，要不要對自己好一點」），但**點到為止、不說教、不診斷**。

## 03 差異化與賣點

一句話：**「一本美到每天想打開看的心情天氣紀錄。」**

- **主打賣點——會累積的氣候圖：** 別的情緒 App 記完就結束，沒有回看價值。這個方向把「時間」變成看得見的東西，用越久越捨不得刪（跟許願池「會長大的樹」同一個護城河邏輯）。
- **零壓力是特色不是妥協：** 故意不做評分、不做連續天數壓力。漏記一天不懲罰、不斷 streak 罵人。賣的是「安心地記錄」，不是「逼你自律」。
- **陰雨天也被溫柔對待：** 壞心情不被畫面懲罰——這是情緒類產品最重要的信任基礎，也是差異化。
- **回顧＝自然分享點：** 「我這一年的情緒氣候」這種年度回顧內容天然會被截圖分享，是低成本的自然流量來源。

## 04 避坑：情緒／習慣類 App 的墳場教訓

- **別做成心理測驗：** 一旦要使用者「評分自己的焦慮程度」就有壓力、也踩醫療線。用「選天氣」這種隱喻式、輕鬆的輸入取代量表。
- **別用 streak（連續天數）當壓力來源：** Habitica 那種「斷了就扣血／有罪惡感」的機制會讓人棄坑。連續紀錄可以當正回饋（累積成就），但**斷了不懲罰**。參考 Finch（養鳥陪伴）靠純鼓勵爆紅。
- **別讓壞心情觸發難看的畫面：** 使用者記錄負面情緒時，畫面若變醜／變懲罰性，等於在說「你有負面情緒是不對的」，這會直接摧毀信任。陰雨、暴雪也要做得美。
- **危機內容的底線：** 若使用者長期記錄極端負面，App 應**常態顯示**求助資源入口（如自殺防治專線），偵測到危機關鍵字時於書寫完成後溫和浮出，不做即時攔截、不打斷。

## 05 商業模式

- **核心免費：** 記錄心情、看氣候圖永遠免費，不設門檻。
- **訂閱制為主：** 去廣告＋進階回顧分析＋更多天氣造型／世界主題（參考 Day One、Reflectly 等日記類做法）。書寫情境跟高頻廣告天生違和，訂閱比廣告更適合這類產品。
- **低價外觀課金：** 直接用真錢標價購買天氣造型、世界主題、音效包，花費透明。
- **廣告（若用）：** 只做自願／激勵式，不打斷記錄流程，類別排除博弈／酒類／借貸。
- **絕對不做：** 隨機／抽獎式付費獎勵（射倖性，踩賭博線）。

## 08 資料模型（雛形）

**User**
- id
- created_at
- deleted_at（軟刪除）

**MoodEntry（每日心情紀錄）**
- id / user_id
- date（一天一筆，重複記錄則更新當天）
- weather_type：晴／多雲／陰／雷雨／霧／雪…
- note（選填，純文字）
- tags（選填，工作／關係／身體…）
- created_at / updated_at
- deleted_at（軟刪除；使用者可隨時刪除自己的紀錄）

**Transaction（若有課金／訂閱）**
- id / user_id
- type：訂閱／課金／花費
- amount / reference_id
- created_at

**ShopItem**
- id / name
- type：天氣造型／世界主題／音效
- price

**關鍵設計：**
- 一天一筆為原則，同日重複記錄視為更新（避免一天多筆造成氣候圖混亂）。
- 全部軟刪除，方便誤刪還原；對使用者呈現上，標記刪除即完全不顯示。

## 09 待決事項

- **天氣種類清單：** 要幾種天氣？各自對應什麼情緒？（太少不夠表達、太多選擇困難，建議先抓 5～7 種）
- **呈現主軸：** 主打「氣候圖」還是「小世界」？（建議 MVP 先做氣候圖，小世界排 Phase 2）
- **一天能不能多筆：** 早上晚上心情不同要不要分開記？（建議一天一筆，簡單優先）
- **帳號模型：** 純裝置 ID 匿名（簡單但換機會掉資料）vs 輕量帳號備份（保資料但多註冊摩擦）。情緒紀錄是長期資產，掉資料很傷。
- **標籤系統要不要做：** 標籤能幫回顧分析，但也增加輸入負擔，要衡量。
- **一句話賣點的最終定版**
