## 共通設計哲學（三個都遵守）

這是從市面上同類 App 的成功（Forest、Finch）與墳場（Habitica、Secret、Whisper）提煉出來的規律，三個方向都建立在這上面：

1. **行為直接長出畫面** — 使用者的行為本身就是遊戲進展，不是「做完事另外給一個無關的小遊戲」。這是留存的根本。
2. **只給正回饋，不給罪惡感** — 漏做一天不懲罰、不扣分、不斷 streak 罵人。Habitica 扣血讓人棄坑，Finch 純鼓勵所以爆紅。
3. **一句話能講完** — Forest 是「別碰手機樹會活」。每個方向都要能濃縮成一句賣點。
4. **儀式感的小動作** — 一個收心的主動作（投香油錢／選天氣／按睡了），配動畫與音效。
5. **純文字、不上圖片** — 繞開 Firebase Storage 免費不能用的雷，也大幅降低內容審核負擔。
6. **常態求助資源入口** — 涉及情緒的方向都要有，危機內容於書寫完成後溫和浮出，不即時攔截。

## 綜合比較表

| 比較項 | 許願池 | 情緒天氣 | 睡眠養成 |
|---|---|---|---|
| **需求強度** | 中（情緒抒發、儀式感） | 中（自我覺察、記錄） | 中高（人人想早睡卻做不到） |
| **開發難度** | 中（兩種流程＋分享安全機制） | 低～中（記錄＋視覺化） | 低～中（打卡邏輯極簡） |
| **技術風險** | 低 | 低 | 中（若接健康資料則升高） |
| **內容安全負擔** | 較高（有公開分享） | 中（情緒內容、危機處理） | 低（幾乎無 UGC 風險） |
| **變現清晰度** | 中（訂閱＋外觀課金） | 中（訂閱為主） | 中（訂閱＋主題課金） |
| **回訪動機** | 強（樹在長、願望在等） | 強（每天記、看氣候圖） | 強（每晚打卡＋世界變化） |
| **分享／傳播點** | 強（一年前的願望實現了） | 強（我這一年的情緒氣候） | 中（本月準時 N 天） |
| **法律敏感度** | 較高（宗教、付費、公益） | 中（非醫療聲明） | 中（非醫療聲明、健康資料） |
| **最大護城河** | 會長大的樹＝時間累積 | 會累積的氣候圖 | 會變美的夜間世界 |
| **最大風險** | 公開分享的隱私與負能量 | 做成有壓力的心理測驗 | 誤入「精準偵測睡眠」的坑 |

## 難度與風險的白話解讀

- **最好上手、風險最低：睡眠養成。** 主動作只有「按睡了」，判斷邏輯就是「打卡時間 vs 目標時間」，幾乎沒有使用者產生的內容要審核，內容安全負擔最小。只要守住「別碰精準偵測睡眠」「晚睡不懲罰」兩條，很難翻車。**適合當作第一個練手、跑完整上架流程的專案。**
- **跟許願池技術最像、能複用最多：情緒天氣。** 記錄＋視覺化累積，跟許願池「行為長出東西」同源，美術與儀式設計幾乎可搬。做完許願池再做這個會非常快。
- **最完整、最有記憶點、但也最重：許願池。** 兩種流程（許願＋告解）、公開分享的安全機制、宗教與付費的法律考量都要處理，是三個裡工程與規劃最厚的。回報是它情感深度與差異化也最強。

## 建議的推進順序（僅供參考）

**如果目標是「先成功上架一個、累積完整經驗」：**
先做 **睡眠養成** → 再做 **情緒天氣** → 最後做 **許願池**。
理由：由簡到繁。睡眠養成邏輯最單純，能最快跑完「從想法到上架」全流程並學到經驗；情緒天氣複用睡眠的視覺與記錄機制；許願池最重，留到最熟練時做，品質最好。

**如果目標是「做最想做、情感最強的那個」：**
直接做 **許願池**（它規劃也最完整了），把睡眠養成、情緒天氣當它驗證成功後的延伸產品線——三者共用同一套引擎、美術風格與後端結構，等於一個 App 的成功可以複製成一個系列。

**共通建議：** 不要三個同時開工。**先讓一個真正做到能給人用、能上架的程度**，過程中學到的東西會讓後兩個快很多。點子不值錢，做出來又有人用才值錢。
